# ADR 0004: Debian/glibc/systemd Release Baseline (v0.1) and musl/dinit Target (v1.0)

- **Status:** Accepted
- **Date:** 2026-11-15
- **Author:** LibreDroid Architecture Team
- **Relevant Subsystems:** [§0 Architecture, §1 Base OS, §2 Display, §3 Bridge]

---

## 1. Context & Problem Statement

A fundamental architectural divergence arose between documentation and implementation:
- **Documented Target:** musl libc + dinit init system + toybox userland + Phosh shell.
- **Working Implementation:** React + TypeScript UI shell, Node.js hardware bridge (`server.js`), Debian package inventory, systemd init/service supervisor, and Cage Wayland kiosk.

These two stacks represent two distinct operating systems sharing a single repository. Attempting to force the current Node/React shell and Chromium kiosk onto a raw musl/dinit/toybox rootfs causes immediate build, display, and graphics driver failures due to Chromium and Cage's deep dependencies on glibc-era Mesa/EGL/Wayland graphics pipelines and systemd session management.

## 2. Decision

1. **v0.1 Release Baseline: Debian / glibc / systemd**
   - Debian Trixie (`amd64`, snapshot `20251101T000000Z`) serves as the foundation for the v0.1 release.
   - Core runtime stack consists of:
     - `glibc` C library and standard Linux userland.
     - `systemd` init and service supervisor (`lrd-shell.service`, `lrd-bridge.service`).
     - `cage` Wayland compositor launching `chromium --kiosk` pointing to the local Node/React shell (`http://127.0.0.1:3001`).
     - Real kernel (`linux-image-amd64`) and modular initramfs (`live-boot`) generated directly inside the target rootfs.
   - Built reproducibly via `mmdebstrap` using Debian snapshot archives.

2. **v1.0 Architecture Target: musl / dinit / FreeStack**
   - The fully independent musl libc, dinit supervisor, and toybox userland become the formal target for v1.0.
   - This migration will occur once native Slint/Rust shell components are stabilized and independent graphics runtimes are decoupled from glibc.

3. **Honest Blob Tiering:**
   - Essential non-free firmware required for bare-metal hardware operation (`firmware-iwlwifi`, `intel-microcode`) is quarantined in the `blob` tier and fully documented in [`docs/BLOBS.md`](file:///home/nitin/fkgugal/docs/BLOBS.md).

## 3. Rationale

- **Working Code Integrity:** The existing working shell code is Node.js and React. Cage and Chromium require glibc-era graphics and Mesa drivers.
- **Immediate Bootability:** `mmdebstrap` produces a functional, booting live ISO immediately, resolving the "overlay without a rootfs" defect.
- **Architectural Coherence:** Halts false claims in documentation and aligns architectural documentation with actual deliverable code.

## 4. Consequences

- **Positive:**
  - Full rootfs generation with true libc, init, kernel, shell, and bridge binaries.
  - Reproducible Debian trixie snapshot pin (`20251101T000000Z`).
  - Working Wayland graphics session inside QEMU and bare-metal UEFI/BIOS machines.
- **Negative / Trade-offs:**
  - Larger image size (~800MB–1GB compressed squashfs compared to a minimal musl rootfs).
  - Ambient dependencies on systemd and Debian package management during the v0.1 lifecycle.
- **Compensating Controls:**
  - Blobs are strictly itemized and isolated to `/lib/firmware` and CPU microcode update loaders.
  - Telemetry blocklists and privacy hooks remain active in the bridge layer.
